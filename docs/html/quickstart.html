烧这个文件 CH572_BLE_LIB/build/out/ble_uart-rom-debug-combined.hex
设置项值为什么
地址偏移不设HEX 自带地址，工具会自动按记录地址写入

这个合并 HEX 的覆盖范围（已解析确认）：

0x00000 - 0x05CEC   应用（调试版，23,892 字节）
0x05CEC - 0x1FFFF   空洞，其中 0x1F000-0x1FFFF 是 SNV 扇区，故意不写
0x20000 - 0x372CB   协议栈 ROM 镜像（94,924 字节）

SHA256 可在 build/out/ble_uart-rom-debug-combined.json 里的 combined_hex_sha256 字段核对。

怎么看这份日志

看哪里正常表现不正常说明什么
[1/4]~[4/4] 四步全过 停在哪一步就是哪一步的问题。调试版还带 9 步 [BLEInit n/9]，能精确定位
VTF 入口: [2]=0x20001205 地址形如 0x200012xx 若是 0x200004B7 / 0x200000DD（ROM 原始值），说明 VTF 被周期校准改回去了 —— 此时功能仍然正常，只是计数无效
BLE中断= 持续增长 一直为 0 且 VTF 入口是 ROM 地址 → 计数被踢出链路；若 VTF 入口是应用地址却仍为 0 → 射频中断真没进来，查 MISC_CTRL / 时钟
最大间隔= 几十到几百 出现 4294963644 这种接近 2³² 的值，是 SysTick 24 位计数器回绕造成的计算假象，不是故障
收到扫描请求 手机一扫就出现 说明广播真的发出去了、射频收发正常
校准后 VTF 被协议栈改回 ROM，已重新武装 约 500 ms 后出现一次，之后每 120 秒一次 这行本身是"周期校准真的在跑"的证据

4. 手机端操作

步骤操作预期
1扫描 BLE 设备看到 CH572-BLE-UART
2连接连接成功，日志出现连接状态变化
3读取服务 0xFFE0 的特征 0xFFE1返回 11（0x0B）
4向 0xFFE2 写入若干字节，再读回读回内容与写入一致 —— 验证普通 GATT 读写
5对 0xFFE4 打开 Notify，再向 0xFFE3 写入 1–20 字节收到上行通知回显 —— 验证 Notify 通路
6读取 0xFFE5（需要认证）触发配对/绑定流程
关于单包长度 默认 BLE_BUFF_MAX_LEN = 27，即 ATT_MTU = 23，单包最多带 20 字节。 写超过 20 字节需要走长写或分包。想提高吞吐就调大 BLE_BUFF_MAX_LEN， 但每档要相应加大 BLE_MEMHEAP_SIZE，并重新检查栈余量。

5. 常见故障对照

现象最可能的原因怎么查
串口完全无输出 接线 / 波特率 / 共地 先量 PA3 有没有波形；确认用的是调试版固件（发布版无输出）
日志停在 [1/4] 之前 ROM 镜像缺失或头部魔数不对 会打印 BLE image missing at 0x00020000；重新烧合并 HEX
停在 [BLEInit 8/9] ROM 的 .data/.bss 没初始化（历史坑） RomRam_Init() 是否在 CH57x_BLEInit() 之前执行
报 head file error ROM 里的版本串与头文件 VER_FILE 不一致 两边都应是 CH572_BLE_PERI_LIB_V1.3；用 make_rom.ps1 重新生成
初始化全过但手机搜不到 射频未工作 查 R32_MISC_CTRL bit24-29 是否设成 0x0E、WindowWidening 是否 120、MAC 是否全 0
打印 >>> 检测到卡死 <<< PC 连续 3 秒不变 拿打印出的 PC 值去 objdump -d 反汇编对应 ELF
打印 ★★★ HardFault ★★★ 非法访问 / 非法指令 看 mepc 指向哪条指令，mcause 常见值：1=取指失败、2=非法指令、5=读非法地址、7=写非法地址

6. 从源码构建

# 进入工程目录
cd CH572_BLE_LIB

# 全量构建：静态库 + ROM 镜像 + 两种方式的应用固件
powershell -ExecutionPolicy Bypass -File scripts\build.ps1 -Target all

# 单独重建调试版（会重生成合并 HEX）
powershell -ExecutionPolicy Bypass -File scripts\build.ps1 -Target rom -DebugBuild

# 自检（37 项，必须全过）

工具链要求 只支持 WCH 官方定制工具链（MounRiver Studio 自带的 riscv-wch-elf-gcc）。 协议栈用了 mcpy 私有指令和 WCH-Interrupt-fast 中断属性， 通用 RISC-V 工具链编不过。脚本会自动探测，也可用 -Toolchain 指定。

7. 改代码时最容易踩的三个坑

坑 1

改了 .ps1 要修 BOM

编辑工具可能吃掉脚本的 UTF-8 BOM，PowerShell 5.1 随后按 GBK 解析中文，报出莫名其妙的语法错。改完跑：

python tools\fix_ps1_encoding.py
python tools\check_ps1_syntax.py
坑 2

-Defines 里不能带逗号

写成 -Defines A=1,B=2 会变成一个宏体，报 token "=" is not valid。要用数组形式：

-Defines @('A=1','B=2')
坑 3

SNV 地址两边必须一致

ch572_ble.h 与生成的 CH572BLE_ROM.h 里的 BLE_SNV_ADDR 必须相同，否则从静态库方式切到 ROM 方式时配对信息全丢。
