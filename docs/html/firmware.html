GATT 服务定义

示例服务 UUID 0xFFE0，包含 5 个特征。这是演示用的服务，做产品时按需替换。

特征UUID属性长度权限用途
CHAR10xFFE1读 / 写1 B可读读回简单参数（返回 11）
CHAR20xFFE2读 / 写20 B可读可写通用数据缓冲区，验证普通 GATT 读写
CHAR30xFFE3只写（含无响应写）20 B只写手机 → 设备（透传下行通道）
CHAR40xFFE4Notify20 B只读 + CCC设备 → 手机（透传上行通道）
CHAR50xFFE5读5 B需认证演示受保护属性，触发配对/绑定
示例的"透传"是回环桩，不是真串口收发 当前 ble_uart_service.c 把手机写进 CHAR3 的数据 memcpy 到 CHAR2 再原样 Notify 回去，完全没有碰 UART 外设，而且在 ATT 写回调（中断上下文）里同步发通知， 失败就静默丢包。做产品要改成官方 BLE_UART 的做法：FIFO + 独立任务 + 按 ATT_MTU-3 分片并重试。

栈是唯一的瓶颈 应用 .bss 的 98% 是 MEM_BUF（协议栈内存堆，5,120 B）。 把它每调小 512 B，栈就多 512 B —— 这是本工程唯一有效的 RAM 调优手段。 链接脚本的下限是 1,024 B，调试版只剩 24 B 余量，任何新增全局变量都要重新确认。

能力边界

✅ 支持

  • BLE 从机（Peripheral）
  • 自定义 GATT 服务（读 / 写 / 写无响应 / Notify / Indicate）
  • 配对与绑定（LE Secure Connections，信息存 SNV）
  • 广播者（Broadcaster）
  • 连接参数更新、MTU 交换、PHY 更新、RSSI 读取
  • 2.4G 私有点对点通信
  • 周期频偏校准

❌ 不支持

  • 主机（Central） —— 不能主动去连别人
  • 观察者（Observer）—— 不能主动扫描
  • GATT 客户端（不能发现别人的服务）
  • 多从机并发连接（只支持 1 条）
  • 扩展广播 / 周期广播 / 周期同步
  • 2.4G 跳频

选型规则 设备是「被别人连」→ CH572 够用。
设备要「主动去连别人」→ 必须换 CH592（它的库有 70 个对象、1,462 个符号，CH572 只有 54 / 841）。

结论：ROM 方式让芯片上多占约 21 KB Flash，换来应用段缩小 85%。 只有在需要 OTA 时才划算 —— 升级包从 86 KB 降到 12.5 KB，而且升级不动协议栈。

发布版与调试版的区别

调试版（-DebugBuild）发布版
DEBUG 宏定义不定义，PRINT 变成空宏
串口输出UART 初始化 + 全部日志无（连 UART 都不初始化）
SysTick10 ms 周期中断，用于卡死检测自由运行计数，关闭 STIE
心跳快照有（约 625 ms 一次）无
HardFault 现场打印有（mcause/mepc/mtval + 栈现场）无
卡死检测器有（PC 连续 3 秒不变就报警）无
VTF 重新武装有（为了 BLE 中断计数）无，中断直接进 ROM 真 ISR
Flash 占用23,892 B12,500 B
可用栈1,048 B1,224 B
发布版的"静默"是设计意图，不是缺陷 发布版不初始化 UART、不打印任何东西，是为了省 Flash 和避免串口引入的功耗与干扰。 但调试版多占 11 KB Flash、少 176 字节栈，且 SysTick 中断更频繁 —— 两者不是同一份代码的行为，发布版必须单独上板确认。

重新生成固件的三种场景

场景命令要重烧什么
只改了应用代码build.ps1 -Target rom只烧应用 HEX（芯片上的 ROM 镜像不变）
换了协议栈库make_rom.ps1 -Lib 新库.a 然后重编应用ROM 镜像 + 应用，用合并 HEX
改了 ROM 基址 / RAM 布局改 make_rom.ps1 -RomBase + Link_rom.ld全部重烧，并擦掉旧 SNV
换 ROM 镜像时切记 如果 ROM 基址或镜像内容变了，必须重新烧 ROM 并重新编译应用。 应用只检查头部魔数（0x43483537），如果 ROM 换了但魔数碰巧一样， 应用会带着不匹配的跳转表继续跑 —— 跳到合法但错误的地址，症状极难排查。
